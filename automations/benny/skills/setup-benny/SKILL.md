# Benny 설정 (Set up Benny)

Benny는 pstack 내부에 비활성 자동화 팩 형태로 포함되어 있습니다. 플러그인 매니페스트는 pstack의 일반 스킬 루트만 노출하며, 이 파일과 두 개의 운영 파일은 슬래시 스킬이 아닙니다.

사람은 Cursor에 팩의 `FOR_AGENTS.md`를 가리키는 것으로 셋업을 시작합니다. 부트스트랩 플로우는 팩 전체를 대상 저장소에 복사한 다음, `.cursor/automations/benny/skills/setup-benny/SKILL.md`에서 이 파일을 직접 읽습니다.

Benny를 사용하려면 외부 설정과 두 개의 라이브 Cursor 자동화(automations)가 필요합니다.

사용자가 명시적으로 요청하기 전까지는 자동화를 생성하거나 업데이트하지 마세요. 플러그인 파일, 프롬프트 또는 커밋되는 설정 파일에 시크릿 값을 절대 넣지 마세요.

## 1. 팩 복사 및 공유 pstack 스킬 활성화

Benny 설정을 물어보거나 내장 `/automate` 스킬을 호출하기 전에 이 단계를 먼저 수행하세요.

어느 저장소에서 자동화를 실행할지 물어봅니다. 소스 팩은 `FOR_AGENTS.md`가 들어 있는 디렉터리입니다. 대상 경로는 `<target-repository>/.cursor/automations/benny/`입니다.

전체 소스 팩을 대상 경로에 병합(merge)합니다:

1. 대상 경로가 없으면 생성합니다.
2. 모든 소스 파일을 동일한 상대 경로로 복사합니다.
3. 대상 경로에만 있는 파일은 보존합니다. 설치나 새로고침 중에 관련 없는 파일을 절대 삭제하지 마세요.
4. 사용자 소유의 설정, 기능 맵(feature map), 라우팅 맵은 대상 경로 바깥에 보관합니다. 이를 절대 덮어쓰지 마세요.
5. 기존 소스 관리 파일의 내용이 다를 경우 diff를 검사하고 로컬 편집 내용을 버리지 않으면서 병합합니다. 소유권이 모호하면 교체하기 전에 멈추고 물어봅니다.
6. 대상 경로에 `FOR_AGENTS.md`, 이 셋업 파일, 두 개의 운영 파일, 참조 문서들 및 템플릿들이 포함되어 있는지 검증합니다.

이 파일을 이미 대상 경로에서 읽고 있다면 복사가 완료된 것으로 간주하고 계속하기 전에 동일한 검증을 실행하세요.

대상 저장소의 `.cursor/settings.json`에 pstack을 추가합니다. 파일이나 `.cursor` 디렉터리가 없으면 생성합니다.

기존 JSON 또는 JSONC에 다음 항목을 병합합니다:

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

관련 없는 모든 최상위 설정과 다른 모든 플러그인 항목을 보존하세요. `plugins.pstack`이 이미 존재하면 `enabled` 값만 변경하세요. 파일이 JSONC를 사용하는 경우 주석과 유효한 JSONC 문법을 보존하세요. 편집 후 파일을 검증하세요.

대상 프로젝트를 다시 로드하거나 그곳을 루트로 하는 새 에이전트를 시작합니다. 다음 공유 pstack 스킬들이 프로젝트 범위(project scope)에서 해석되는지 확인합니다:

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

현재 세션이나 사용자 범위(user-scoped) 플러그인에서 로드된 스킬은 세지 마세요. 이 점검은 대상 저장소의 새로운 에이전트가 프로젝트 설정을 통해 pstack을 제공받는다는 것을 보여주어야 합니다.

프로젝트 범위 플러그인 설치를 사용할 수 없거나 공유 의존성 중 하나라도 해석되지 않으면 멈추고 실패 원인을 설명하세요.

Benny 파일들은 `.cursor/automations/benny/`에서 직접 읽힙니다. 해당 디렉터리를 플러그인 매니페스트에 추가하거나 그 안의 `SKILL.md` 파일들이 슬래시 스킬 목록에 나타나기를 기대하지 마세요.

어느 한쪽 자동화라도 활성화하기 전에 `.cursor/settings.json`, `.cursor/automations/benny/`, 그리고 참조된 시크릿 없는 설정 파일들이 반드시 커밋되어야 한다고 사용자에게 안내하세요. 사용자가 요청하지 않는 한 직접 커밋하지 마세요.

이 점검을 통과하면 라이브 자동화 프롬프트는 안정적인 저장소 상대 경로를 통해 커밋된 운영 파일을 읽을 수 있습니다. 플러그인 캐시 경로를 내장하거나 파일 내용을 직접 복사해서 넣지 마세요.

## 2. 설정 파일 작성

복사된 다음 예시 파일들을 엽니다:

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

`.cursor/automations/benny/` 바깥에 사용자 소유 사본을 생성합니다. 이 파일들은 팩 파일이 아니라 설정 파일입니다. 위치 예시:

- 프로젝트 설정: `.cursor/benny/configuration.yaml` 등
- 프로젝트 기능 맵: `.cursor/benny/feature-map.md` 등
- 프로젝트 라우팅 맵: `.cursor/benny/routing.md` 등
- 사용자 설정: `~/.config/benny/configuration.yaml` 등
- 사용자 기능 맵: `~/.config/benny/feature-map.md` 등

자동화가 재현할 수 있는 모든 사용자 대면 기능마다 기능 맵 섹션을 하나씩 작성합니다. 사용자 관점을 유지하세요. 세부 구현 사항이나 현재 코드 경로를 맵에 고정해 두지 마세요.

복사된 예시 파일 자체는 편집하지 마세요. 팩 새로고침은 충돌 검토 후 소스 관리 파일을 업데이트할 수 있지만, 사용자 소유 사본은 절대 건드려서는 안 됩니다.

새로운 자동화 체크아웃이 읽어야 하는 경우 대상 저장소에 커밋된 시크릿 없는 파일을 우선 사용하세요. 그렇지 않다면 필요한 값들을 라이브 프롬프트에 풀어서 설명(paraphrase)하세요. 내장 `/automate` 스킬이 자동화가 실행되는 저장소에 해당 파일이 커밋되었음을 확인한 후에만 저장소 파일을 참조하세요.

커밋된 팩 및 설정 파일에는 안정적인 저장소 상대 경로를 사용하세요. 라이브 자동화에서 플러그인 소스 디렉터리나 플러그인 캐시 경로를 절대 참조하지 마세요.

## 3. 필수 선택 항목 채우기

다음 항목을 물어보거나 확인합니다:

- 소스 Slack 채널 ID
- 선택적 운영(operations) 또는 상태 채널 ID
- 저장소 URL 및 기본 브랜치
- 트리아지 ID(identity) 또는 Slack 사용자 ID
- 이슈 트래커 종류, 팀, 프로젝트, 레이블 및 인테이크(intake) 상태
- 트래커 어댑터 스킬 또는 MCP 액션
- 선택적 라우팅 맵 경로
- 필수 컨트롤 스킬 이름
- 필수 사용자 관점 기능 맵 경로
- 상태 이모지 문자열
- 풀 리퀘스트 URL 형식
- 폴링 및 공수 예산(budgets)
- 트리아지, 재현, 코드 작업 및 미디어 검토용 모델 슬러그(slug)

사용자의 Cursor 모델 선택기나 지원되는 모델 목록에 사용 가능한 것으로 표시된 모델 슬러그만 사용하세요. 슬러그를 추측하거나 비공개 기본값을 그대로 가져와 쓰지 마세요.

소스 채널, 트리아지 ID, 저장소, 트래커 어댑터, 컨트롤 스킬 및 기능 맵은 명시적이어야 합니다. 필수 값 중 하나라도 모호하게 남아 있으면 셋업을 실패 처리하세요.

최종 자동화 이름, 설명 및 프롬프트 심(shim)을 저장하기 전에 pstack의 `unslop` 스킬을 적용하세요.

## 4. 연동 기능 점검

트리아지 자동화에는 다음이 필요합니다:

- 설정된 소스 Slack 채널과 그 스레드에 대한 읽기 권한
- 해당 채널에서의 스레드 답글 권한
- 제보에 미디어가 포함된 경우 첨부 파일 메타데이터 및 파일 다운로드 권한
- 설정된 이슈 트래커 어댑터를 통한 검색, 읽기, 생성 및 업데이트 권한

재현 자동화에는 다음이 필요합니다:

- 소스 스레드 읽기 권한
- 소스 채널에서의 스레드 답글 권한
- 설정된 운영 채널에서의 선택적 게시 및 편집 권한
- 저장소 읽기 및 히스토리 접근 권한
- 드래프트 풀 리퀘스트를 열 수 있는 풀 리퀘스트 액션
- 설정된 컨트롤 어댑터 스킬

읽기와 게시에는 설정된 Cursor Slack 액션을 우선 사용하세요. 선택적인 `BENNY_SLACK_BOT_TOKEN`은 운영 상태 메시지 하나를 편집하거나 첨부 파일을 다운로드하는 등 부족한 좁은 범위의 공백을 메우는 데 사용할 수 있습니다. 해당 값은 YAML이 아니라 시크릿 매니저나 환경 변수에 저장하세요.

문서화되지 않은 연동 엔드포인트는 사용하지 마세요.

## 5. 라우팅 맵 준비

사용자가 리라우트(reroute)나 오너 호출(owner ping)을 원하는 경우 다음을 수행합니다:

1. `../triage-issue-reports/references/routing.example.md`를 `.cursor/automations/benny/` 바깥으로 복사합니다.
2. 모든 플레이스홀더를 공개 값 또는 조직 내부 값으로 교체합니다.
3. 오너 호출은 기본적으로 꺼 둡니다.
4. 설정된 기능 오너 또는 확인된 유력 회귀 작성자(regression author)에 대해서만 호출을 허용합니다.

라우팅 맵이 설정되지 않은 경우 트리아지는 제보를 분류할 수는 있지만 목적지나 오너를 추측해서는 안 됩니다.

## 6. 컨트롤 어댑터 검증

`../reproduce-and-fix-issues/references/control-adapter.md`와 사용자의 작성 완료된 기능 맵을 읽습니다.

지정된 스킬이 다음을 수행할 수 있는지 확인합니다:

- 대상 앱 기동
- 실제 UI를 통해 매핑된 모든 기능 탐색
- 선언된 어댑터 액션을 통해 매핑된 상태 실행
- 결과를 강제하지 않고 상태 검사
- 스크린샷 캡처
- 녹화 시작 및 중지
- 프로세스 및 임시 데이터 정리(clean up)

어느 기능이라도 누락되어 있다면 재현 자동화는 비활성 상태로 두세요. 수행하지 않은 재현을 수행했다고 주장하는 대신 안전하게 실패 후 종료(fail closed)해야 합니다.

## 7. 라이브 자동화 준비

이번 작업이 최초 생성인지 기존 자동화의 설정 변경인지 물어봅니다.

어느 경로든 복사된 팩의 `../../FOR_AGENTS.md`를 기본 사용자 의도 소스로 읽습니다. 이를 통해 두 트리거, 도구, 지침, 결과 및 공통 규칙을 파악하세요.

### 최초 생성 (First-time creation)

한 번에 하나의 자동화만 생성합니다.

각 자동화에 대해 다음을 수행합니다:

1. 보조 내부 소스 자료로 일치하는 복사된 프롬프트 템플릿을 읽습니다.
2. `FOR_AGENTS.md`, 완성된 Benny 설정, 템플릿 의도를 완전한 자연어 요청으로 변환합니다.
3. 라이브 프롬프트가 `.cursor/automations/benny/` 아래의 커밋된 정확한 운영 파일을 읽고 따르도록 지시합니다.
4. 플러그인 소스나 캐시 경로가 아니라 안정적인 저장소 상대 경로를 사용합니다. 운영 파일의 내용을 라이브 프롬프트에 복사해 넣지 마세요.
5. 내장 `automate` 스킬을 읽고 따릅니다.
6. `automate`가 Slack 채널, 저장소, 연결된 연동 기능을 탐색하도록 합니다.
7. 복사된 팩과 참조된 모든 설정 파일이 자동화가 실행될 동일한 저장소에 커밋되었음을 `automate`가 확인하도록 합니다.
8. `automate`가 초안 표를 보여주고, 승인을 얻고, 준비 상태를 묻고, Automations 에디터를 열도록 합니다.
9. 다음 자동화를 시작하기 전에 현재 자동화의 에디터 인계를 완료합니다.

`automate`에 설정 값으로 채워진 다음의 완전한 트리아지 의도를 전달합니다:

- 이름: `benny-triage`.
- 매 실행마다 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽고 따릅니다.
- 설정된 소스 Slack 채널의 새로운 최상위 제보마다 트리거됩니다.
- 트리거된 스레드를 읽고 그 스레드 안에서만 답글을 남깁니다.
- 설정된 이슈 트래커 연동을 사용합니다.
- 분류하고, 증거를 검사하고, 원인을 추적하고, 중복을 제거(dedupe)하며, 명확한 신규 버그에 대해서만 티켓을 생성합니다.
- 스레드 전용 단일 판정 메시지의 끝을 설정된 `[benny:bug]`, `[benny:performance]`, 또는 `[benny:other]` 마커 및 선택적 트래커 URL로 마무리합니다.
- 소스 채널 루트 메시지는 절대 게시하지 않습니다.

트리아지 에디터 인계가 완료된 후 `automate`에 다음의 완전한 재현 및 수정 의도를 전달합니다:

- 이름: `benny-reproduce`.
- 매 실행마다 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽고 따릅니다.
- 설정된 소스 Slack 채널의 동일한 신규 최상위 제보에서 트리거됩니다.
- 설정된 저장소와 기본 브랜치를 사용합니다.
- 소스 스레드를 읽고 그 스레드 안에서만 답글을 남깁니다.
- 풀 리퀘스트 생성 기능과 설정된 트래커, 컨트롤 어댑터 및 기능 맵 요구사항을 포함합니다. 동일한 저장소에 적격한 커밋된 파일이 있음을 `automate`가 확인한 경우가 아니라면 매핑된 사용자 경로와 상태를 풀어서 설명(paraphrase)합니다.
- 행동하기 전에 신뢰할 수 있는 트리아지 마커를 기다립니다.
- 매핑된 실제 UI를 통해 정확한 증상을 두 번 재현하고 증거를 캡처합니다.
- 기존 수정 사항을 덮어쓰지 않고 검증합니다.
- 확인된 재현 후에만 선택적인 범위 제한 수정(bounded fix)을 시도하고, 증명과 검사가 통과할 때 드래프트 풀 리퀘스트를 엽니다.
- 소스 채널 루트 메시지는 절대 게시하지 않습니다.

`automate`가 수행하는 Slack, 저장소, 연동, 완전성, 인증, 초안 검토, 승인, 준비 상태 점검 또는 에디터 인계 작업을 중복해서 수행하지 마세요.

### 기존 자동화 (Existing automations)

내장 `automate` 스킬은 생성 전용입니다. 기존 자동화를 검색, 검사 또는 업데이트하는 데 사용하지 마세요.

설정, 라우팅, 컨트롤 어댑터 및 기능 맵 검증을 마친 뒤 사용자에게 다음의 간결한 에디터 체크리스트를 제공합니다.

기존 트리아지 자동화에서 업데이트할 항목:

- 이름 및 설명
- `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽으라는 직접 지침
- 신규 최상위 Slack 제보 트리거 및 소스 채널
- Slack 스레드 읽기 및 답글 권한
- 이슈 트래커 연동
- 패러프레이즈된 트리아지 지침, 스레드 전용 규칙 및 Benny 판정 마커

기존 재현 자동화에서 업데이트할 항목:

- 이름 및 설명
- `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽으라는 직접 지침
- 일치하는 Slack 트리거 및 소스 채널
- 저장소 및 기본 브랜치
- Slack 스레드 읽기 및 답글 권한
- 풀 리퀘스트 액션
- 트래커, 컨트롤 어댑터 및 기능 맵 요구사항
- 패러프레이즈된 마커 대기, 증거, 검증 및 범위 제한 수정 지침

사용자에게 Automations 에디터에서 각 기존 자동화를 직접 업데이트하도록 요청하세요. 대체본이나 중복 자동화를 만들지 마세요.

### 생성 경계 (Creation boundary)

직접 자동화 백엔드 서비스나 백엔드 자동화 도구를 절대 호출하지 마세요. 초안 필드를 담은 브라우저 URL을 절대 사용하지 마세요. Cursor 프로토콜 딥링크를 만들거나 열지 마세요. 신규 자동화의 유일한 완료 경로는 내장 `automate` 스킬의 검토를 거친 Automations 에디터 인계뿐입니다.

에디터 저장 후 스레드 안전성 테스트를 통과할 때까지 어느 자동화도 활성화하지 마세요.

## 8. 스레드 안전성 테스트

테스트 채널이나 무해한 테스트 제보를 사용합니다.

테스트하기 전에 자동화 체크아웃이 사용하는 브랜치에 대상 저장소의 `.cursor/settings.json`, `.cursor/automations/benny/`, 그리고 참조된 모든 시크릿 없는 설정 파일이 커밋되어 있는지 확인하세요. 두 라이브 프롬프트가 모두 커밋된 정확한 운영 파일을 가리키는지 확인하세요. 어느 점검이라도 실패하면 즉시 중단하고 사용자에게 아직 자동화를 활성화할 수 없다고 안내하세요.

다음을 검증합니다:

1. 트리아지가 루트 `thread_ts`를 저장하고 정확히 하나의 판정 메시지를 답글로 게시합니다.
2. 판정 메시지에 설정된 마커가 하나 포함되어 있습니다.
3. 재현 자동화가 설정된 트리아지 ID로부터 온 마커만 수락합니다.
4. 재현 자동화가 동일한 불변 소스 좌표를 유지합니다.
5. 소스 채널에 루트 메시지가 나타나지 않습니다.
6. 위임된 워커가 어떠한 Slack 쓰기 액션도 사용할 수 없습니다.
7. 좌표 누락, 삭제된 부모 메시지 또는 사전 점검(preflight) 실패 시 게시물도 올리지 않고 트래커 이슈도 생성하지 않습니다.

일곱 가지 점검을 모두 통과한 후에만 일반 트래픽에 대해 활성화하세요.
