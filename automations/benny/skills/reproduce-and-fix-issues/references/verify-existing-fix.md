# 기존 수정 사항 검증 (Verify an existing fix)

열려 있는 풀 리퀘스트나 머지된 커밋이 제보된 이슈를 해결할 가능성이 높을 때 이 모드를 사용하세요.

기존 아티팩트가 수정을 소유합니다. 이를 검증하세요. 기존 아티팩트를 편집하거나, 경쟁하는 패치를 작성하거나, 다른 풀 리퀘스트를 열지 마세요.

## 아티팩트 자격 판별 (Qualify the artifact)

다음 중 하나의 구체적인 아티팩트가 필요합니다:

- 증상을 다루는 코드 변경이 포함된 열려 있는 풀 리퀘스트
- 머지된 풀 리퀘스트
- 일치하는 코드와 의도를 가진 머지된 커밋

풀 리퀘스트나 커밋이 없는 스레드 내 주장, 트래커 상태, 브랜치 이름 또는 원인 가설만으로는 충분하지 않습니다.

여러 아티팩트가 존재하는 경우 소스 스레드나 트래커에서 링크된 것을 선택하세요. 그렇지 않으면 영향받는 코드와 가장 가깝게 일치하는 것을 선택하고 그 이유를 명시하세요.

## 워킹 트리 보호 (Protect the working tree)

저장소가 지원하는 경우 격리된 워크트리(worktree)나 다른 깨끗한 체크아웃을 사용하세요. 사용자의 변경 사항을 덮어쓰지 마세요.

다음을 기록합니다:

- 베이스라인 리비전
- 패치된 리비전
- 풀 리퀘스트 또는 커밋 URL
- 두 실행이 공유하는 빌드 및 환경 입력

일반 `github.com` 풀 리퀘스트 링크를 사용하세요.

## 베이스라인 측정 (Measure the baseline)

열려 있는 풀 리퀘스트의 경우 해당 베이스 브랜치를 베이스라인으로 사용합니다.

머지된 수정의 경우 수정 직전의 리비전이 빌드 가능하고 이전 동작을 나타낸다면 해당 리비전을 사용합니다.

설정된 컨트롤 어댑터를 통해 다음을 수행합니다:

1. 베이스라인 앱을 기동합니다.
2. 올바른 앱과 환경을 확인합니다.
3. 실제 UI 액션을 통해 제보된 경로를 실행합니다.
4. 구별 가능한 증상을 관찰합니다.
5. 초기화하고 이를 반복합니다.
6. 베이스라인 녹화본, 스크린샷 및 상태 점검 결과를 캡처합니다.

베이스라인에서 증상이 두 번 나타나지 않으면 베이스라인이 성립하지 않은 것입니다. 수정이 작동한다고 주장하지 마세요.

## 패치된 빌드 측정 (Measure the patched build)

동일한 환경과 데이터로 풀 리퀘스트 또는 수정 커밋을 빌드하고 실행합니다.

1. 동일한 UI 경로를 실행합니다.
2. 이를 두 번 반복합니다.
3. 깨진 상태가 사라졌는지 확인합니다.
4. 기대 상태가 나타나는지 확인합니다.
5. 수정 후(after) 녹화본, 스크린샷 및 동일한 상태 점검 결과를 캡처합니다.

컴파일이나 테스트 단계에서 멈추지 마세요. 수정 후 결과는 실행 중인 패치된 앱으로부터 나와야 합니다.

## 결과 처리 (Outcomes)

### 확인됨 (Confirmed)

베이스라인에서 두 번 재현되고 패치된 빌드에서 두 번 해결된 경우입니다.

- 운영 상태를 검증 완료(verified)로 표시합니다.
- 아티팩트를 링크합니다.
- 소스 사전 점검(preflight) 후 간결한 소스 스레드 답글을 하나 게시합니다.
- 전후(before and after) 결과를 포함합니다.
- 풀 리퀘스트는 열지 않습니다.

### 불충분한 수정 (Insufficient fix)

베이스라인과 패치된 빌드 모두에서 증상이 나타나는 경우입니다.

- 운영 상태를 재현되었으나 수정되지 않음(reproduced but not fixed)으로 표시합니다.
- 아티팩트를 링크하고 증상을 해결하지 못했음을 알립니다.
- 이번 실행에서 아직 일반 재현 확인 소스 업데이트를 보내지 않았다면 이를 게시합니다.
- 경쟁하는 풀 리퀘스트는 열지 않습니다.

### 판단 불가 (Inconclusive)

베이스라인이 재현되지 않거나, 패치된 앱을 실행할 수 없거나, 증거에 구별 가능한 상태가 나타나지 않는 경우입니다.

- 성공했다고 주장하지 마세요.
- 어느 쪽 절반을 측정할 수 없었는지 명시합니다.
- 결과는 운영 스레드나 실행 출력에 유지합니다.
- 직접적인 질문에 답해야 하는 경우가 아니라면 소스 스레드에는 아무것도 게시하지 마세요.

## 정리 (Cleanup)

두 빌드를 모두 중지하고, 보존 정책에 따라 임시 프로필과 캡처 파일을 제거하며, 사용자의 작업물을 버리지 않고 저장소를 이전 상태로 되돌립니다.
