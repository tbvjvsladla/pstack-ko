# 컨트롤 어댑터 계약 (Control-adapter contract)

Benny는 모든 앱을 시작하거나 구동하는 방법을 자체적으로 알지 못합니다. 사용자는 대상 앱에 대해 이 계약을 구현하는 하나의 컨트롤 스킬 또는 어댑터를 설정해야 합니다.

스킬 이름은 `control.skill_name`에 설정하세요.

작성이 완료된 사용자 관점 기능 맵(feature map) 경로는 `control.feature_map_path`에 설정하세요. 복사된 예시 파일을 직접 수정하는 대신 `.cursor/automations/benny/` 바깥에 [`feature-map.example.md`](./feature-map.example.md)을 복사하여 내용을 채우세요.

스킬, 기능 맵 또는 필수 기능이 없거나 모호하거나 불완전하면 재현 및 수정 작업은 반드시 안전하게 실패 후 종료(fail closed)해야 합니다.

## 필수 기능 (Required capabilities)

### 기동 (Bring up)

요청된 테스트 환경에서 요청된 앱 리비전(revision)을 시작합니다.

입력:

- 저장소 및 리비전
- 빌드 또는 시작 모드
- 워크스페이스, 계정, 픽스처(fixture) 및 기능 상태 요구사항
- 아티팩트 디렉터리
- 작성 완료된 기능 맵 경로

반환:

- 세션 식별자
- 어댑터가 올바른 앱과 환경을 확인한 방법
- 안정적인 앱 마커
- 이후 호출에 필요한 실행 중인 프로세스 또는 타깃 세부 정보
- 누락된 기능 목록

어댑터는 대상 앱을 유사한 창, 셸 또는 프로덕션 인스턴스와 구별해야 합니다.

### UI 구동 (Drive UI)

실제 사용자 액션을 수행합니다:

- 클릭(Click)
- 타이핑(Type)
- 키 입력(Press keys)
- 스크롤(Scroll)
- 드래그(Drag)
- 리사이즈(Resize)
- 앱 컨트롤을 통한 내비게이션

역할(role), 레이블, 안정적인 셀렉터를 우선 사용하세요. 좌표는 새로운 스크린샷을 찍은 직후에만 사용하세요.

각 액션과 관찰된 상태 변화를 반환합니다.

증상을 만들어내기 위해 내부 상태를 직접 설정하거나, 숨겨진 앱 메서드를 호출하거나, 스토리지에 직접 쓰거나, DOM 변경을 주입하지 마세요.

### 매핑된 기능 및 상태 구동 (Drive mapped features and states)

앱을 구동하기 전에 관련 기능 맵 섹션을 읽습니다.

어댑터는 다음을 수행할 수 있는 수단을 노출해야 합니다:

- 사용자에게 보이는 경로를 통해 매핑된 모든 기능을 탐색합니다.
- 해당 기능에 나열된 어댑터 액션 이름을 호출합니다.
- 해당하는 경우 기본(default), 호버(hover), 포커스 표시(focus-visible), 활성(active), 비활성(disabled), 로딩(loading), 빈 상태(empty), 에러(error), 선택됨(selected), 열림(open), 펼쳐짐(expanded) 및 기능별 고유 상태와 상호작용합니다.
- 안전한 픽스처 데이터, 권한, 플래그, 서비스 응답 또는 지원되는 테스트 컨트롤을 통해 상태를 준비(arrange)합니다.
- 두 번째 독립적인 재현 시도를 위해 기능을 초기화(reset)합니다.
- 기능 맵에 명시된 스크린샷, 비디오 및 읽기 전용 교차 검증(cross-check)을 캡처합니다.

역할(role), 접근 가능한 이름(accessible name), ARIA 관계, 안정적인 컴포넌트 마커, 그리고 목적에 따라 명명된 data 속성을 사용하세요. 생성된 CSS 또는 StyleX 클래스, 동적 해시, 자식 인덱스 또는 깨지기 쉬운 DOM 위치는 절대 사용하지 마세요.

사전 조건을 준비하는 것이 제보된 증상을 직접 주입해도 된다는 허가는 아닙니다. 재현 자체는 여전히 실제 사용자 상호작용으로부터 나와야 합니다.

### 상태 검사 (Inspect state)

UI가 보여주는 내용을 확인하기 위해 상태를 읽습니다.

예시:

- 접근성 트리(Accessibility tree)
- DOM 또는 뷰 계층 구조(view hierarchy)
- 프로세스 상태
- 로컬 로그
- 네트워크 요청 상태
- 앱이 노출하는 디버그 상태

검사는 읽기 전용입니다. 쿼리가 상태를 변경한다면 그것은 `Drive UI`에 속하며 실제 사용자 액션을 나타내야 합니다.

### 스크린샷 (Screenshot)

현재 앱 상태를 요청된 경로에 캡처합니다.

반환:

- 파일 경로
- 캡처 시각
- 앱 마커 또는 창 제목
- 화면에 보여야 하는 내용에 대한 짧은 설명

스크린샷에는 올바른 앱을 테스트 중임을 증명할 수 있을 만큼 충분한 앱 크롬(chrome)이 나타나야 합니다.

### 녹화 (Recording)

전체 재현 경로 전후로 화면 녹화를 시작하고 중지합니다.

반환:

- 파일 경로
- 시작 및 중지 시각
- 캡처된 창 또는 영역
- 오디오 또는 민감한 오버레이가 생략되었는지 여부

녹화본에는 셋업이나 로딩 화면뿐만 아니라 구별 가능한 최종 상태가 반드시 나타나야 합니다.

### 정리 (Cleanup)

어댑터가 생성한 프로세스와 세션을 중지합니다.

일회용 리소스를 제거합니다:

- 브라우저 또는 앱 프로필
- 임시 워크스페이스
- 어댑터가 생성한 테스트 계정 또는 픽스처
- 디버그 포트 및 터널
- 보존 기간이 지난 캡처 파일

중지되었거나, 제거되었거나, 보존되었거나, 사람을 위해 남겨둔 항목을 반환합니다.

정리 작업이 사용자의 작업물을 삭제해서는 안 됩니다.

## 어댑터 동작 (Adapter behavior)

어댑터는 반드시 다음을 준수해야 합니다:

- 재현이 시작되기 전에 지원 기능을 보고합니다.
- 기능 맵 섹션 중 구동 가능한 섹션과 차단된(blocked) 섹션을 보고합니다.
- 베이스라인 빌드와 패치된 빌드에 동일한 환경 입력을 사용합니다.
- 시작 실패를 숨기지 않고 실패로 드러냅니다.
- 재시도 횟수를 제한합니다.
- 로그와 아티팩트에 시크릿이 포함되지 않게 합니다.
- 캡처 파일을 저장소 바깥에 보관합니다.
- 두 번의 재현 시도 사이에 새로운 상태 또는 초기화된 상태를 지원합니다.
- 사용자가 안전한 테스트 액션을 명시적으로 설정한 경우가 아니라면 프로덕션 변경을 피합니다.

## 환경 변환 (Environment translation)

환경에 의한 차단(block)을 선언하기 전에 플랫폼 종속적인 명사를 빼고 결함을 다시 기술한 뒤, 가용한 환경에서 동일한 동작을 안전하게 테스트할 수 있는지 자문해 보세요.

예시:

- 특정 브라우저 이름은 임의의 외부 브라우저를 의미할 수 있습니다.
- 특정 키 이름은 설정된 단축키를 의미할 수 있습니다.
- 특정 원격 호스트 이름은 지연되거나 연결이 끊긴 원격 타깃을 의미할 수 있습니다.

변환된 시도는 동일한 기저 동작을 테스트할 때만 사용하세요. 그리고 이를 변환된 증거(translated evidence)로 레이블링하세요. 누락된 환경 자체가 결함의 일부인 경우에는 이를 정확한 재현이라고 부르지 마세요.

하드웨어 프롬프트, 운영체제 권한 대화상자, 기기 전용 API, 사용할 수 없는 계정 상태는 실제 차단 요인이 될 수 있습니다.

## 셋업 점검 (Setup check)

재현 자동화를 활성화하기 전에 무해한 어댑터 점검을 1회 실행하세요:

1. 앱을 기동합니다.
2. 안정적인 앱 마커를 확인합니다.
3. 작성 완료된 기능 맵 섹션 하나를 로드합니다.
4. 사용자 경로를 통해 해당 기능으로 이동합니다.
5. 매핑된 어댑터 액션을 통해 일회용 상태 하나를 실행해 봅니다.
6. 결과 상태를 검사합니다.
7. 스크린샷을 캡처합니다.
8. 짧은 클립을 녹화합니다.
9. 정리(clean up)합니다.

아홉 단계가 모두 성공하고 소스 채널 Slack 게시가 전혀 개입되지 않은 경우에만 재현 작업을 활성화하세요.
