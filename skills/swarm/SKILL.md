# Swarm

## 시작 (Start)

무엇이든 실행하기 전에 단계별로 항목 하나씩을 담은 할 일 목록(todolist)을 먼저 여세요.

1. Frame (틀 잡기)
2. Fan out (팬아웃)
3. Aggregate (집계)
4. Report (보고)

## Phase A: Frame (틀 잡기)

1. 완료 조건(done predicate)과 스웜이 반환해야 할 아티팩트 또는 보고서를 명시하세요.
2. 형태를 선택하세요. 조각(slice)으로 분할하거나, 동일한 브리핑으로 N개의 워커를 경쟁(race)시키거나, 두 방식을 혼합합니다. 레이스 또는 혼합 형태의 경우 워커를 띄우기 전에 `first pass`, `rank all`, 또는 `best-of` 중 선택 규칙을 먼저 선언하세요.
3. `~/.cursor/rules/pstack-models.mdc`의 `swarm workers` 줄에서 워커 모델을 선택하세요. 규칙이나 해당 줄이 없으면 `grok-4.7-xhigh-fast`를 사용합니다. `auto` 또는 `inherit-parent`인 경우 워커가 부모 모델에서 실행되도록 `model`을 생략하세요. Task 도구가 슬러그를 거부하면 기본값을 사용하고 그 사실을 알리세요. 기본값도 거부하면 에러 메시지에서 동일한 패밀리의 가장 가까운 유효한 슬러그를 사용하세요. 모델 간 레이스의 경우 각 갈래(arm)의 모델을 사전에 명시하세요. **poteto-mode** 스킬의 Subagents 섹션에 따라 작업에 맞는 각 서브에이전트의 추론 수준과 속도(빠름 또는 표준)를 선택하세요.
4. 워커가 쓰기 작업을 수행할 때는 각 워커마다 고유한 쓰기 가능한 출력 경로를 부여하세요. 워커가 커밋을 검증하거나 측정할 때는 각 브리핑에 정확한 SHA를 명시합니다. 측정 브리핑에는 측정 방법(표본 크기, 단일 표본의 정의, 순서)도 함께 명시합니다. 워커는 결과에 두 가지 모두를 기록해야 합니다.

## Phase B: Fan out (팬아웃)

하나의 메시지에서 `subagent_type: generalPurpose`, `environment: "cloud"`, `run_in_background: true`, 그리고 3단계에서 선택한 모델(`auto` 또는 `inherit-parent`인 경우 비워둠)을 지정하여 N개의 워커를 모두 띄우세요. 워커가 사용자 컴퓨터에 있는 자원에 접근해야 할 때만 `environment: "local"`을 사용하세요.

워커가 기본 브랜치가 아닌 푸시된 브랜치에서 시작해야 할 때는 `cloud_base_branch`를 전달하세요.

모든 브리핑은 그 자체로 완결성을 가져야 합니다. 목표, 범위, 정확한 담당 조각 또는 레이스 갈래, 검증 방법, 보고할 내용을 포함하세요. 보고서는 근거와 함께 `PASS`, `ISSUES`, 또는 `BLOCKED`를 사용합니다. 결함을 증명할 수 있는 워커는 `ISSUES`를 보고하며, 첫 번째 결함뿐만 아니라 증명할 수 있는 모든 이슈를 나열합니다.

중도에 탈락(drop out)하는 워커가 있으면 N-1개로 계속 진행하고 그 사실을 기록하세요.

## Phase C: Aggregate (집계)

종료된 결과들을 읽으세요. 브리핑이 지정한 SHA와 측정 방법을 기록하지 않은 결과는 버리고 해당 워커를 한 번 다시 띄우세요. 두 번째에도 누락되면 공백(gap)으로 기록합니다. 공백은 통과(pass)로 인정되지 않습니다. 커버리지 작업의 경우 필수 조각마다 결과가 있어야 합니다. 레이스의 경우 사전에 선언한 선택 규칙(`first pass`, `rank all`, 또는 `best-of`)을 적용하세요. 워커의 날것(raw) 출력 덤프를 그대로 붙여넣지 마세요.

## Phase D: Report (보고)

결과 표, 한 줄 요약된 이슈들, 공백 또는 중도 탈락 내역, 그리고 레이스인 경우 적용한 레이스 규칙을 담아 채팅창에 하나의 통합 보고서로 반환하세요.
