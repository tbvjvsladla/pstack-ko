# 공유 상태는 직렬화하기 전에 먼저 분리하라 (Separate Before Serializing Shared State)

동시에 실행되는 액터들이 동일한 파일, 브랜치, 키, 또는 객체에 쓰기 작업을 할 가능성이 있다면, 먼저 그들에게 하나의 공유 객체가 필요한지 아니면 각자 독립적인 사실을 발행하고 있는지를 질문하세요. 기본적으로 각 액터에게 고유한 파일, 키, 브랜치, 또는 상태 디렉터리를 부여하고, 상태를 읽는 지점에서만 병합하세요. 두 워커가 하나의 `state.json` 안에 각자의 필드를 쓰는 것 역시 여전히 공유 변이(shared mutation)입니다.

단일 공유 쓰기 대상이 진짜 불변식일 때만 접근을 구조적으로 직렬화하세요(락 파일, 단일 작성자, 순차적 단계, compare-and-swap). 지침은 동시성 제어가 아니며, "락이 필요하다"는 생각은 먼저 점검해 보아야 할 설계 냄새(smell)입니다.
