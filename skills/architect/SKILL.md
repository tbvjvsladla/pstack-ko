# Architect

코드를 작성하기 전에 변경이 건드리는 모든 시스템을 추적한 뒤, 서로 다른 두 가지 형태(타입, 시그니처, 모듈 경계)를 스케치하고 각 상태가 단 하나의 소유자(owner)를 가지며 각 작업마다 단 하나의 수행 방식만 존재하고 호출자가 알아야 할 내용이 가장 적은 형태를 선택하세요. 우회책(workaround)이 반복된다면 땜질하지 말고 다시 설계하세요.

규모가 크거나 이견이 있는 설계의 경우 혼자 스케치하지 말고 **arena** 스킬을 실행하세요.
