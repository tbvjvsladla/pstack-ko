# 도메인을 모델링하라 (Model the Domain)

도메인을 조건문들에 흩뿌리는 대신 데이터 구조 안에 인코딩하세요. 올바른 구조는 유효하지 않은 상태를 표현 불가능하게 만들고 분기문을 제거합니다.

흩어진 불리언(boolean) 변수나 단계(phase) 체크 대신 상태 머신을, 느슨한 파라미터 대신 타입이 지정된 모델을, 여러 파일에 퍼져 있는 분기문 대신 맵(map)·레지스트리·구별된 유니온(discriminated union)을, 즉흥적인 상태 변경 대신 리듀서(reducer)를, 그리고 접근 패턴이 요구하는 곳에서는 인덱스·큐·정규화된 컬렉션을 활용하세요.

억지로 강제하지는 마세요. 형태가 명확하고 국소적이며 앞으로 커질 가능성이 낮다면 평범하고 지루한 코드를 유지하고, 분기문이나 유효하지 않은 상태를 제거하지 못하면서 간접 참조만 늘리는 추상화는 경계하세요.

이 원칙을 건너뛰었다는 신호: 기능을 추가할 때 `if/else` 체인에 분기를 하나 더 늘리거나, 첫 번째 불리언과 동기화를 유지해야 하는 두 번째 불리언을 추가하는 경우입니다.
