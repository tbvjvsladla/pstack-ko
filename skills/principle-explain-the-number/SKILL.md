# 수치를 설명하라 (Explain the Number)

- **실행하기 전에 의사결정 기준을 적으세요.** 결정을 바꾸게 될 결과 수치와 노이즈 플로어(noise floor)를 명시하세요. 실행 간 편차(spread)가 효과보다 크다면 중단하세요.
- **"왜 두 배 더 좋지 않을까?"라고 질문하세요.** 실행 중에 수집한 프로파일이나 카운터에서 근거를 얻어 결과를 제한하는 자원이나 코드 경로를 특정하세요. 코드를 읽고 추측한 것은 제한 요인(limiter)이 아닙니다.
- **그 수치가 측정했을 수도 있는 다른 가능성들을 나열하고**(에러, 건너뛰었거나 캐시된 작업, 아예 실행되지 않은 코드, 튜닝되지 않은 비교 대상, 노이즈, 무의미할 정도로 작은 부분 등), 각각의 가능성을 증거로 배제하세요.
- **수치와 함께 실행 횟수, 편차(spread), 제한 요인(limiter)을 보관하세요.**

성능 수치의 경우 [benchmark-checklist](../benchmark-checklist/SKILL.md) 스킬을 실행하세요. 평가(eval) 결과의 경우 모든 실행이 과업을 실제로 수행했는지, 시행과 모델을 달리해도 격차가 유지되는지, 그리고 시나리오가 실질적인 의미를 가지는지 질문하세요.
