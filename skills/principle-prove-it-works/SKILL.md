# 작동함을 증명하라 (Prove It Works)

모든 과업 산출물은 실제 대상을 직접 확인하여 검증하세요. 대리 지표(proxy), 자체 보고, 또는 "컴파일이 된다"는 사실로부터 추론하지 마세요.

**이유:** 검증되지 않은 작업은 올바른지 알 수 없습니다. 간접 검증(파일 수정 시각, 산출물의 최신성, 에이전트의 자체 보고, 캐시된 스크린샷)은 직접 관측하는 것보다 저렴해 보이지만, 잘못된 추론을 바탕으로 행동하는 비용은 원본을 직접 확인하는 비용보다 훨씬 더 비쌉니다.

대리 지표가 아니라 실물을 확인하세요:
- 파생된 상태를 통한 간접 확인이 아니라 프로세스의 생존 여부(liveness)를 직접 확인하세요
- 캐시되거나 파생된 표현이 아니라 실제 값을 읽으세요
- 검증이 실패하면 시스템을 의심하기 전에 관측 방법부터 의심하세요

## 가능하면 검증을 스크립트로 작성하세요

가장 강력한 증명은 한 번 눈으로 훑어보는 것이 아니라 동일한 비교를 다시 실행할 수 있는 결정론적 스크립트입니다. 스크립트를 작성하고 실행한 뒤, 리뷰어가 당신의 말만 믿는 대신 직접 재실행해 볼 수 있도록 그 출력을 아티팩트로 남기세요.

사람이 볼 수 있게 아티팩트를 가시적으로 유지하세요. 대규모 포팅이나 마이그레이션처럼 나중에 감사(audit) 추적이 필요한 크고 복잡한 작업의 경우에만 해당 아티팩트를 커밋하세요(**show-me-your-work** 스킬 참고).
