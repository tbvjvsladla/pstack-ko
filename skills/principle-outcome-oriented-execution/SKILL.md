# 결과 지향적 실행 (Outcome-Oriented Execution)

매끄러운 중간 상태를 유지하는 것보다 의도한 검증 가능한 최종 상태(end state)에 맞게 최적화하세요.

**이유:** 모든 중간 단계를 완벽히 안정적으로 유지하려 하면 대개 임시 호환성 코드를 만들게 되고, 이는 오랫동안 남는 기술 부채가 됩니다. 목표 아키텍처로 수렴시키고 명시적인 검증 경계에서 정합성을 증명하세요.

**핵심 규칙:**
- 과도기적 안정성보다 최종 상태의 무결성을 우선시하세요
- 중간 단계의 깨짐(breakage)은 계획되었고 범위가 통제되며 되돌릴 수 있는 한 허용됩니다

**가드레일:**
- 명시적인 단계 경계가 있는 계획된 재작성 및 마이그레이션에 이 원칙을 사용하세요
- 일시적인 깨짐이 허용되는 범위를 명확히 선언하세요
- 마이그레이션하는 동안 활발히 건드리고 있는 영역에 대해서는 고신호(high-signal) 검증을 유지하세요
- 계획이 완료되는 시점에는 전체 정적 검증 및 런타임 검증을 필수로 통과하세요
