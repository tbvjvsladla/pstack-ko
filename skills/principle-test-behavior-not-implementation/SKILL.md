# 구현이 아니라 동작을 테스트하라 (Test Behavior, Not Implementation)

테스트는 코드의 사용자가 그 인터페이스를 통해 관측할 수 있는 것—반환값, 에러, 다시 읽어 들일 수 있는 상태, 외부 시스템에 미치는 효과—에 대한 주장입니다. 비공개 헬퍼, 내부 호출 순서, 중간 단계 데이터는 구현입니다.

각 테스트를 두 가지 가상의 편집 상황에 비추어 평가하세요:

- **동작을 깨뜨려 보세요**(잘못된 값, 건너뛰거나 두 번 실행된 효과). 그래도 테스트가 여전히 통과한다면 아무것도 증명하지 못하는 것입니다. 흔한 원인은 느슨한 단언문(assertion), 테스트 대상 코드가 직접 계산해 낸 기댓값, 그리고 테스트가 스스로 조립한 데이터에 대한 단언문입니다.
- **내부 구현을 바꾸되** 관측 가능한 모든 결과는 유지해 보세요. 테스트가 실패한다면 내부 구현에 묶여(pinned) 있는 것입니다.

첫 번째 편집은 잡아내고 두 번째 편집에서는 살아남는 테스트만 유지하세요. 나머지는 다시 작성하거나 삭제하세요. 구체적인 입력으로 퍼블릭 인터페이스를 통해 코드를 구동하고, 요구사항으로부터 기댓값을 도출하세요. 외부 서비스가 수신하는 것은 동작입니다. 내부 헬퍼에 대한 호출은 동작이 아닙니다. "이 일은 절대 일어나지 않는다"는 테스트에는 실제로 그 일이 일어나는 케이스를 짝지어 구성하세요. 메시지 문구가 아니라 호출자가 분기 처리의 기준으로 삼는 에러 타입을 단언하세요.
