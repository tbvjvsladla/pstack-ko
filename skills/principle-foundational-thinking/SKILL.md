# 기반 중심 사고 (Foundational Thinking)

**구조적 결정**은 옵션 가치(option value)를 보호합니다. **코드 수준 결정**은 단순함을 보호합니다.

**데이터 구조가 먼저입니다.** 로직을 작성하기 전에 데이터의 형태(shape)를 올바르게 잡으세요. 핵심 타입을 일찍 정의하고, 모든 접근 패턴을 추적하며, 지배적인 실행 경로에 부합하는 구조를 선택하세요.

코드 수준에서는 모든 줄이 아니라 구조를 DRY(중복 배제)하게 만드세요. 타입과 데이터 모델은 하나로 수렴해야 합니다. 섣부른 추상화보다는 유사한 구문 세 줄이 여전히 낫습니다. 기교 부린 코드보다 명시적인 코드를 선호하세요. 줄 수가 아니라 동작과 엣지 케이스를 테스트하세요.

**동시성 따름정리:** 액터 간에 상태를 공유하기 전에 "다른 액터가 이를 동시에 수정하면 무슨 일이 벌어지는가?"라고 질문하세요. 답이 "아무 일도 없다"가 아니라면 격리하세요.

**스캐폴드를 먼저 구축하세요.** 이후의 모든 단계에 도움이 되는 작업이라면 가장 먼저 수행하세요. "이후의 모든 단계가 이것의 존재로부터 이득을 얻는가?"라고 질문하세요. CI, 린팅, 테스트 인프라, 공유 타입은 스캐폴드입니다. 옵션 가치를 위해 순서를 배치하세요: 기능보다 설정을 먼저, 수정보다 테스트를 먼저 두세요. 커밋은 작고 단일한 목적을 갖도록 유지하세요.

각 증분(increment)은 일관된 추상화를 안착시키거나 기존 추상화를 심화해야 합니다. 새로운 기능을 여러 호출자에 걸친 특수 케이스 조율 로직으로 흩뿌리지 마세요.

스캐폴딩보다 먼저 해야 할 일은 뺄셈입니다. 죽은 코드를 먼저 제거한 다음 기반을 다지세요.
