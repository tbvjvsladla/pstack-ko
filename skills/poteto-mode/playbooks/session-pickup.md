### 세션 이어받기 (Session pickup)

**재개 지점(resume point)에 대한 소유권은 당신에게 있습니다. 이전 흔적(trail)을 읽으세요. 처음부터 다시 하지 마세요.**

1. 이전 흔적을 찾으세요. 활성 워크스페이스의 `agent-transcripts/` 디렉터리 아래에 있는 로컬 트랜스크립트(시스템 프롬프트가 경로를 지정합니다. `~/.cursor/projects/*/` 전체를 글로빙하지 마세요. 워크스페이스 경계를 넘어 무관한 프로젝트의 비공개 채팅을 읽게 됩니다), 클라우드 에이전트 URL, 또는 푸시된 브랜치를 확인합니다. 메타데이터 개요와 마지막 메시지들을 먼저 읽은 다음, 거슬러 올라가며 의사결정 지점들을 스캔하세요. 긴 트랜스크립트는 서브에이전트에서 파싱하고 메인 스레드에는 압축된 타임라인만 유지하세요(**principle-guard-the-context-window** 스킬). 서브에이전트(Subagents) 섹션에 따라 작업에 맞게 각 서브에이전트의 추론 수준과 빠른(fast) 또는 표준(standard) 속도를 선택하세요.
2. 운영 상태를 재구성하세요. 브랜치와 워크트리, 이미 반영된 내역(`git log`, 베이스 대비 `git diff`), 열려 있는 할 일(todos), 내려진 결정들을 파악합니다. 이전 흔적은 권위 있는(authoritative) 입력값입니다. 이를 처음부터 다시 도출하려는 편향에 저항하세요.
3. 완료된 작업 대 남은 작업을 비교(diff)하세요. 계획된 내용 대비 실제 배포된 내용을 비교하고, 재개 지점을 명시하며, 이전 재현을 다시 실행하거나 이미 완료된 작업을 다시 하지 마세요. "처음부터 다시 검증해 보겠습니다"라는 식의 패스는 권위 있는 흔적을 신뢰할 수 없는 것으로 취급하고 있다는 뜻입니다.
4. 남은 작업을 매칭되는 플레이북으로 라우팅하고 판정을 선택하세요: 실행 계속 진행, 완료된 추천안 배포, 이전 결론 추인(ratify) 또는 번복(override), 혹은 실패한 실행의 사후 분석(postmortem) 중 하나입니다. 세션 이어받기 플레이북은 여기서 끝납니다. 그 이후는 라우팅된 플레이북이 소유합니다.
5. 물려받은 주장들을 실제 산출물 위에서 원래 목표와 대조해 검증하세요(**principle-prove-it-works** 스킬). 통과했다는 이전 에이전트의 자기 보고(self-report)는 증명이 아닙니다.

**응답(Reply):** 이전 에이전트가 멈춘 지점, 물려받은 작업 대 다시 수행한 작업(이상적으로는 다시 수행한 작업이 없어야 함), 재개 지점, 그리고 최종 결과.
