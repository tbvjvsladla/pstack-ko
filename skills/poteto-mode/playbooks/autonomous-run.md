### 자율 실행 (Autonomous run)

**종료 조건(exit condition)에 대한 소유권은 당신에게 있습니다. 완료를 정의하고 멈추지 말고 그 상태까지 몰고 가세요.**

1. 첫 번째 반복(iteration)을 시작하기 전에 종료 조건을 검증 가능한 조건식(checkable predicate)으로 명시하세요(테스트 그린, 재현 케이스 수정됨, N개의 PR 모두 머지됨, 픽셀 diff 0 등).
2. Cursor의 `/loop` 명령어(pstack 스킬이 아닌 내장 기능)를 사용하여 깨우기 메커니즘(wake mechanism)을 선택하세요. 감시할 이벤트(CI, 머지, ref 전진)가 있다면 이벤트 발생 시 당신을 깨우는 워처(watcher) 서브에이전트를 두고 긴 시간 기반 하트비트를 폴백으로 설정합니다. 이벤트가 없다면 결과를 다시 확인할 가치가 있는 주기에 맞춘 고정 간격 하트비트를 사용합니다. 서브에이전트(Subagents) 섹션에 따라 작업에 맞게 각 서브에이전트의 추론 수준과 빠른(fast) 또는 표준(standard) 속도를 선택하세요.
3. 각 반복에서는 증거가 정당화하는 가장 작은 변경을 수행하고, 조건식에 비추어 검증하며, 진전이 있었다면 커밋하고 도움이 되지 않은 변경은 폐기합니다. "도움이 될지도 모르는" 과잉 방어 코드(belt-and-suspenders)는 그대로 두지 말고 되돌리세요(revert).
   마지막에 검증을 몰아서 하는 대신 **sequence-verifiable-units** 원칙 스킬을 통해 각 단위를 다음 단위로 넘어가기 전에 검증하며 작업을 순서화하세요.
4. 실행 도중 발견된 목표 달성에 도움이 되는 사항들은 당신의 몫입니다. 고장 난 스킬, 관련 버그, 불안정한 검증기(flaky verifiers), 리뷰 노이즈, 도구 실패, 주인 없는 후속 작업, 수정 가능한 드리프트를 poteto-mode를 통해 직접 해결하세요. 본 작업 흐름 외의 수정(out-of-band fixes)은 별도의 PR로 분리하세요. 되돌릴 수 있는 작업을 사람에게 미루어 두거나 `AskQuestion`을 사용하지 마세요. 되돌릴 수 없는 행동, 어떤 실험으로도 해결할 수 없는 진정한 제품·선호도 결정, 또는 실제 막다른 길(dead end)만 수면 위로 올리세요. 조건식을 주된 동력으로 유지하고 각 부수적 수정이 끝나면 즉시 조건식 달성으로 복귀하세요.
5. **show-me-your-work** 스킬을 통해 매 반복마다 무엇이 바뀌었고 조건식이 진전되었는지를 한 행으로 기록하여 체크포인트를 남기세요.
6. 조건식이 충족되면 멈추세요. 정체기(plateau)는 멈출 이유가 아니므로 계속 진행하며 접근법을 전환(pivot)해 돌파하세요. 제자리걸음을 반복하는 대신 진정한 막다른 길은 보고하고, 승리를 선언하기 위해 조건식을 절대 완화하지 마세요.

**응답(Reply):** 종료 조건, 실행한 반복 횟수, 반영된 변경사항, 폐기된 변경사항, 최종 조건식 상태.
