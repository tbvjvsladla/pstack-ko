### 조사 (Investigation)

**답변에 대한 소유권은 당신에게 있습니다. 계획하고, 라우팅하고, 작성하세요.**

조사 요청은 읽기 전용입니다. 코드 변경이 아니라 인용이 포함된 설명이나 추천을 산출합니다.

1. **how** 스킬을 통해 라우팅하세요. 동기(motivation)에 관한 질문이라면 **why** 스킬을 통해서도 라우팅하세요.
2. 처리량 체크포인트는 한 줄로 유지합니다: `throughput checkpoint: n/a, read-only investigation`.
3. `how` 형태의 출력(Overview / Key Concepts / How It Works / Where Things Live / Gotchas)을 생성하거나, 요청이 대안들 사이의 결정이라면 트레이드오프 표가 포함된 추천안을 작성하세요.
4. 응답에 **unslop** 스킬을 적용하세요.

조사가 코드 변경에 선행하는 경우가 아니라면 PR 생성도, 베이비시팅도, `architect` 실행도 하지 않습니다. 코드 변경이 뒤따르는 경우라면 사용자에게 결과를 먼저 돌려주고 Bug fix 또는 Feature로 다시 라우팅하세요.

**응답(Reply):** 조사 결과 출력. "이게 확실한가(are we sure)?"라는 질문에 대한 답변에는 이유를 포함한 실제 본인의 판단을 담으세요. 전제가 틀렸다면 반론을 제기하세요(자율성(Autonomy) 섹션 참조).
