### 다단계 또는 다중 PR 계획 (Multi-phase or multi-PR plan)

**당신은 코드가 아니라 계획(plan)을 소유합니다. 계획은 소유자(owner)가 체크박스를 하나씩 실행하고 운영자(operator)가 증거로부터 감사(audit)하는 체크리스트입니다.** 계획 자체가 산출물입니다. 직접 구현하지 마세요.

1. 변경사항이 파일 한두 개 수준이고 접근법이 자명하다면 계획을 건너뛰세요. 그렇다고 말하고 멈추세요.
2. 작성하기 전에 `playbooks/prototype.md`에 따라 프로토타입으로 미결 질문을 먼저 해결하세요. 운영자에게는 어떤 실행으로도 해결할 수 없는 제품 또는 선호도 결정에 대해서만 질문하세요.
3. 계획 파일을 작성하세요. 무엇이 바뀌는지, 반영 순서대로 나열한 PR ID 목록, 그리고 어떤 PR들이 독립적이어서 트렁크에서 분기하는지·어떤 PR이 무엇을 기다리는지·각 PR이 건드릴 수 있는 파일 범위를 밝히는 의존성 그래프로 시작합니다. 그다음 PR당 하나의 섹션을 작성합니다. 하나의 PR은 자체적인 증거를 가진 하나의 변경입니다(**sequence-verifiable-units** 원칙 스킬). 각 섹션에는 의존 대상, 편집하는 파일, 구축하는 단일 변경, 확인되는 결과, 그리고 검증에 대한 체크박스를 둡니다.
4. 테스트만으로는 충분한 검증이 되지 않습니다. PR은 단위(unit), 라이브(live), 성능(perf) 체크박스가 모두 체크되었을 때만 검증된 것으로 인정됩니다. 각 라이브 체크박스는 구체적인 시나리오와 통과 조건식(pass predicate)으로 실제 표면을 구동합니다. 성능 체크박스는 지표, 프로브(probe), 먼저 측정한 트렁크 베이스라인, 그리고 실패 기준 수치를 명시합니다. 인터랙션을 변경하는 PR은 머지 전에 운영자의 리뷰를 기다립니다.
5. 계획 파일 경로를 돌려주고 멈추세요. 실행은 운영자의 명시적인 실행 승인(go)이 떨어졌을 때 시작됩니다.

**응답(Reply):** 계획 파일 경로, 의존성 및 리뷰 게이트 대상 세트가 포함된 PR ID 목록, 그리고 아직 증명되지 않은 사항.
