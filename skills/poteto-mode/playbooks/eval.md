### 평가 (Eval)

**실험 설계에 대한 소유권은 당신에게 있습니다. 계획하고, 블라인드 처리하고, 실행하고, 종합하세요.**

**블라인드 처리를 위한 타협 불가 원칙:**

- 후보(candidate)가 보는 어떤 디렉터리, 파일, 프롬프트에도 `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, 또는 `arena`라는 단어가 들어가서는 안 됩니다.
- 후보 프롬프트는 자연스러운 실제 사용자 요청처럼 보여야 합니다. 메타 설명이 아니라 목표를 진술하세요.
- 체인 유도 단서(chain-eliciting cues)를 주지 마세요. 후보에게 어떤 스킬, 원칙, 또는 파일을 적용했는지 나열하라고 요청하지 마세요. 일반적인 설계 노트를 요청하고, 체인 준수 여부는 자기 보고(self-report)가 아니라 코드 형태로부터 채점하세요.
- 디렉터리와 슬러그 이름을 정화(sanitize)하세요. 사용자가 실제로 고를 법한 프로젝트 형태의 이름을 사용하세요.
- 후보에게 다른 후보들이 존재한다는 사실을 알리지 마세요.
- 심사위원(judge)은 자신이 심사 중이라는 사실을 알 수 있지만, 모델 이름이 아니라 정화된 라벨로만 산출물을 봅니다.
- 두 변형(variant)을 비교할 때는 한 명의 심사위원이 어느 세트에서 나온 것인지 모른 채 단일 패스에서 하나의 척도로 두 세트를 모두 채점합니다.

**단계:**

1. **프레임 설정 (Frame).** 어떤 변형이 테스트 대상인지, 그리고 어떤 동작이 성공으로 간주되는지 명시하세요. 심사위원 전용 루브릭(3~6개의 구체적인 기준)을 작성하세요. 후보들에게는 루브릭을 공개하지 마세요.
2. **정화된 환경 구축 (Set up sanitized environments).** 해당 변형이 적용된 후보별 작업 디렉터리를 준비합니다. 실제 작업이라면 당연히 있을 법한 컨텍스트(프로젝트 스켈레톤, 후보가 자연스럽게 읽게 될 스킬들)를 심어 두세요.
3. **자연스러운 단일 프롬프트 작성 (Author one organic prompt).** 실제 사용자가 입력할 법한 문구로 작성합니다. 무엇이 측정되고 있는지에 대한 단서가 유출되어서는 안 됩니다.
4. **N개의 병렬 후보 생성 (Spawn N parallel candidates).** **arena** 스킬의 Phase B에 따라 서로 다른 모델들로 N개의 병렬 후보를 생성합니다. 각 후보는 자신의 정화된 디렉터리에서 작업하며 동일한 프롬프트를 받습니다. 서브에이전트(Subagents) 섹션에 따라 작업에 맞게 각 서브에이전트의 추론 수준과 빠른(fast) 또는 표준(standard) 속도를 선택하세요.
5. **블라인드 심사위원 1명 생성 (Spawn one blinded judge).** **arena** 스킬의 Phase C에 따라 다른 모델 패밀리로 한 명의 블라인드 심사위원을 생성합니다. 심사위원은 모델 이름이 아니라 정화된 라벨과 루브릭으로만 산출물을 봅니다.
6. **자기 보고가 아닌 트랜스크립트로부터 체인 검증 (Verify the chain from transcripts, not self-report).** 활성 워크스페이스의 `agent-transcripts/` 디렉터리(시스템 프롬프트가 이 경로를 지정함) 아래에서 각 후보의 로컬 트랜스크립트를 읽으세요. `~/.cursor/projects/*/` 전체를 글로빙(glob)하지 마세요. 그렇게 하면 워크스페이스 경계를 넘어 무관한 프로젝트의 비공개 채팅을 읽게 됩니다. 각 후보가 실제로 어떤 파일들을 열었는지 확인하세요. 체인 준수 여부는 후보 자신의 주장이 아니라 실제로 읽은 파일들과 코드의 형태로부터 채점하세요.
7. **모든 후보의 산출물을 처음부터 끝까지 직접 읽기 (Read every candidate output yourself).** 심사위원의 판정과 비교하세요. 불일치가 있다면 모델이 편향되었거나 루브릭이 모호하다는 뜻입니다. 결과를 종합(synthesize)하세요.

**응답(Reply):** 테스트 대상 변형, 루브릭, 후보별 노트, 심사위원의 판정, 당신의 종합 의견, 그리고 해당 변형을 정식 반영(promote)할지에 대한 추천.
