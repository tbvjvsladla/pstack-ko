### 런타임 포렌식 (Runtime forensics)

**진단에 대한 소유권은 당신에게 있습니다. 소스를 보고 이론을 세우지 말고 라이브 프로세스를 계측(instrument)하세요.** 산출물은 수정이 아니라 인용이 포함된 진단입니다.

1. 제어(control) 스킬을 통해 해당 표면에서 라이브 신호를 캡처하세요: 무한 회전(spinning)하는 프로세스에는 CPU 프로파일, 메모리 누수에는 힙 스냅샷, 시각적 글리치에는 CDP 트레이스를 캡처합니다. 추측이 아니라 실제 산출물이어야 합니다.
2. 산출물을 결정적 증거(smoking gun)로 압축하세요: 핫 패스(hot path) 위의 함수, 누수된 객체에서 GC 루트까지 이어지는 리테이너 체인(retainer chain), 입력 없이 발화하는 루프 등입니다. 대용량 산출물은 서브에이전트에서 파싱하고(**guard-the-context-window** 원칙 스킬), 메인 스레드에는 압축된 발견 사항만 유지하세요. 서브에이전트(Subagents) 섹션에 따라 작업에 맞게 각 서브에이전트의 추론 수준과 빠른(fast) 또는 표준(standard) 속도를 선택하세요.
3. 메커니즘을 믿기 전에 먼저 증명하세요. 실행 중인 프로세스에 CDP eval로 계측 코드를 주입하거나 리로드 없이 라이브 코드를 핫픽스하여 가설을 저렴하게 확인하세요.
4. 발견 사항을 소스에 매핑하세요: 파일, 심볼, 그리고 할당(allocate)하거나 스케줄링하는 라인을 찾으세요.
5. 처리량 체크포인트는 한 줄로 유지합니다: `throughput checkpoint: n/a, read-only forensics`.

**응답(Reply):** 캡처한 신호, 압축된 발견 사항, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로. 요청받지 않았다면 수정은 하지 마세요. 원인이 파악되면 Bug fix 또는 Perf issue로 돌려보내세요.
