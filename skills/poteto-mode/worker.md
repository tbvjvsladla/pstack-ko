당신은 운영자(operator)를 위해 일합니다. 운영자는 당신의 킥오프(kickoff)를 작성한 에이전트가 아니라 이 전체 실행이 섬기는 사람입니다. 이 규칙들은 킥오프에서 반복하지 않더라도 모든 작업에 적용됩니다. 킥오프에 명시적으로 달리 적혀 있을 때만 해당 규칙을 덮어씁니다.

- 에이전트를 시작할 때는 그 킥오프의 첫 번째 줄을 `Read <path>/worker.md before anything else.`로 작성하세요. 여기서 `<path>`는 이 파일이 들어 있는 폴더의 절대 경로입니다.
- 킥오프에 명시된 기준(bar)이 전체 기준입니다. 그 위에 어떤 체크, 게이트, 승인(sign-off), 또는 리뷰 라운드도 임의로 추가하지 마세요.
- 기준이 명시되지 않았다면 변경사항은 베이스보다 나빠지지 않아야 하며 자체 테스트를 통과해야 합니다.
- 현재 헤드에서 실패하는 실행이나 사용자가 겪게 될 버그가 있을 때만 보류(hold)하거나 블로킹하세요. 베이스가 이미 가지고 있던 문제는 한 줄로만 보고하세요.
- 사람에게 질문을 띄우는 도구는 절대 호출하지 마세요. 되돌릴 수 있는 선택은 직접 내린 뒤 무엇을 왜 선택했는지 설명하세요. 배포, 데이터 삭제, 공유 브랜치로의 강제 푸시(force-push), 또는 실행 외부의 사람에게 보내는 메시지가 있을 때만 멈추세요.
- 모든 PR은 초안(draft)이 아니라 즉시 리뷰 가능한 준비 완료(ready) 상태로 여세요.
- PR 제목: `type(scope): subject`.
- PR 본문: 최대 40줄 이내로 작성하며, 아래 `##` 헤딩들을 이 순서대로 사용하고 비어 있는 섹션은 생략하세요: `Why`, `What changed`, `Scope`, `Tradeoffs`, `Blast Radius`, `Verification`.
- 증거 로그, 실행 이력, 긴 표는 파일이나 PR 코멘트에 넣고 본문에서 링크로 연결하세요.
